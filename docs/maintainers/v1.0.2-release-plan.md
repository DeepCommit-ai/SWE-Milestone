## 2. Harness changes

### R1 — validate filter lists, subtract the verified intersection (`harness/e2e/evaluator.py`)
- `filter_evaluation_result` reduces `pass_to_pass_required` by `min(len(invalid_p2p), required)`
  (L2545-2549): a count, not an intersection. Add `validate_filter_list(filter_list, classification,
  milestone_id) -> list[str]` next to `load_filter_list` (L2352): every `invalid_pass_to_pass` id must be in
  `stable_classification.pass_to_pass`; every `invalid_fail_to_pass` / `invalid_none_to_pass` id in
  `fail_to_pass ∪ none_to_pass` (the evaluator merges the two keys at L2473, so validation is per bucket);
  no duplicate within or across keys; `version` absent or 1; `condition` absent or null.
- `filter_evaluation_result` gains an optional `p2p_universe`; when given, L2547 subtracts
  `len(invalid_p2p & p2p_universe)`. When None, byte-identical to today (all 93 existing lists and every
  stored result keep reproducing; measured over-subtraction today: 0 cells).
- `generate_filtered_evaluation` (L2600) passes the classification's P2P set; on a validation error it writes
  no filtered file, renames an existing one to `.stale`, and stamps `filter_list_error` + `scoring_blocked:
  true` on the raw result. `run_e2e` preflight and `rescore.py` call the validator and refuse to start on error.
- Tests: unknown / duplicate / wrong-bucket / bad-version entries; absent-universe equivalence.

### R2 — `rescore.py --mode filter-only`
- Today `rescore_cell` returns `already-identity` (L596-612) before `mirror_dir` (L737) and
  `_regenerate_filtered` (L468-491): after #24 is promoted, `--mode mirror` writes nothing.
- New mode: inputs = the stored raw `evaluation_result.json` (never a filtered file), the pinned
  classification (L520-533), the validated filter list (L709), `ran_test_ids`. No replay selection (it
  would strand the 368 non-replayable and 288 frozen pass-wins published cells, including 1 of the 46 W1
  flips). `ran_test_ids` = union over `artifacts/*/eval.json`, exactly as `generate_filtered_evaluation`
  (evaluator L2637-2650) — and `check_record_consistency.py:72-73` must use the same rule, otherwise 3
  published cells disagree on `pass_to_pass_missing` and fail the gate forever. Locks via
  `_regenerate_filtered` verbatim. Output per cell under `--out/mirror/<repo>/<trial>/<cell>/`: byte-identical
  copy of the raw result (required by `promote_cells.py:138-139`), regenerated
  `evaluation_result_filtered.json`, `rescore_manifest.json`, `PROMOTION_NOTES.md`; no `artifacts/` copy.
  Status per cell `promoted | non-promotable:<reason> | error:<reason>`; any `error:` exits non-zero
  (today `main` always returns 0, L988). `promote_cells.py` needs no change.

### R3 — release gate: derivative missing
- `scripts/check_record_consistency.py:60-67` `_filtered_drift` returns ok when a cell has no filtered file.
  When the milestone has a non-empty validated filter list and the cell has no derivative, fail with
  `derivative missing for a universe with a filter list`. W1 creates 1,524 derivatives and regenerates 395;
  without R3 a half-finished campaign passes `release.sh [0/5]` while serving raw results.

  the `pass_to_pass_missing` adjustment and do not reproduce from raw; 7 scikit `M12.5` cells with a filtered

- Order witness: the harness's own `collect_results.load_e2e_execution_order` orders milestones by the
  summary timestamps; with that rule 478 entries have at least one passing witness in a cell evaluated after
  the owner's event (48 after an owner event that was itself `passed`). This does not disprove a conflict (a
  resolved owner need not have implemented the exact owner behaviour) but it is why blanket filtering removes
  some passing obligations (the 271 `score_full` decreases). A trial-aware variant (apply an entry only where
  the owner precedes the victim in that trial's order) is being quantified side by side; 47 retry cells have
  no tag lineage and would be left unfiltered.
- Blanket vs trial-aware, authoritative cells (`retally_trialaware.json`, `A_filters.md` §5.5):

  | variant | entry-applications | cells changed | resolved F→T / T→F | `score_full` ↑ / ↓ | Σ Δ `score_reliable` |
  |---|---:|---:|---:|---:|---:|
  | blanket | 24,599 / 24,599 | 1,262 | 46 / 0 | 1,030 / 271 | +61.7 |
  | trial-aware (i) owner completed earlier | 9,421 (38.3 %) | 1,084 | 45 / 0 | 944 / 140 | +53.7 (87 %) |
  | trial-aware (ii) owner completed earlier and resolved | 1,404 (5.7 %) | 278 | 31 / 0 | 239 / 39 | +15.6 (25 %) |

  Undecidable conditions: 0 in the authoritative population (59 entry-applications in 13 superseded retry
  dirs, left unfiltered). The `score_full` decreases do not vanish under trial-aware (filtering any passing
  obligation next to unfiltered failures lowers `achieved/required`); they are ≤ 0.13 pp per cell and the
  aggregate rises under all three formulas. Reading (ii) is not defensible: in most trials the owner cell
  failed although the agent had written the owner code, which is the conflict itself.
- Decision A (maintainer): (i) blanket (recommended: +1 flip, +13 % score gain, no schema / evaluator /
  gate change; disclose the 48 owner-resolved witnesses and the 440–480 owner-before counts with the
  campaign) vs trial-aware (i) (needs a `condition` entry field, a per-cell order input in
  `filter_evaluation_result` / `rescore.py`, and a gate change); (ii) keep the avoidable (197) and latent
  (130) obligations in the set (recommended: the published trials saw the SRS as it was) or restrict to
  unavoidable (entries 848 → 521, effect unmeasured).

## 4. W5 — crash-hidden tests (deferred; kept for the record)

Measured on main today (`D_issue23_reeval.md`): the shipped jest IPC guard is on by default and works for
IPC-serialization crashes (probe B), but the #23 class — process-fatal unhandled rejection — is not
recovered by it: probe A re-evaluated a qualifying cell and reproduced the published tally id for id.
**A campaign with today's harness is a proven no-op.** Gate for W5 (decision B):

1. Build the missing piece: an `unhandledRejection` handler in the same `--require` preload that records the
   rejection and fails the running test instead of letting Node kill the worker (keeps failure semantics
   visible; `--unhandled-rejections=warn` was rejected: not semantically neutral, hung one milestone 26 min).
   Validate against both fullprobe conditions before any campaign.
2. Ruling on legacy snapshots: 54 of 67 qualifying cells have no integrity sidecar and need
   `--allow-legacy-snapshot` (documented as not promotion-grade); only 13 (`glm-5.2-1m`) are
   promotion-grade. Either extend the v1.0.1 precedent explicitly or accept a single-trial campaign
   (a fairness problem: one trial gains ~8.6 element points while identically affected trials do not).
3. Land W2 first (removes 19 of the 67 cells outright).

Then: re-scan immediately before launch (`scan_issue23.py`, `build_cells_json.py`; the record drifts),
campaign dir `SWE-Milestone-log/reeval/issue23_<date>/` with `EXPECTATION.md` (declared direction: inside the
crashed suites `missing -> pass|fail`; outside, every id unchanged; any `achieved -> missing` stops the
campaign), per-cell `python3 -m harness.e2e.evaluator ...` exactly as `probe_cell.sh`, comparison rule,
`scripts/promote_cells.py --layout campaign --cells-file ... --campaign issue23_<date>`, release gate.
Machine time: 82 s per jest cell (64 cells ≈ 20 min at concurrency 6) plus a separate 2.5–5 h lane for the
3 `feature_enhancements` playwright cells. Expect score movement, not resolve movement (0 flips measured and
projected).
