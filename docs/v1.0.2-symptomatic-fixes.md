# Spec: v1.0.2 symptomatic fixes for cross-universe obligations (EBAO path)

Status: **draft v1 (2026-08-21), pending adversarial review** · Owner: harness/e2e + SWE-Milestone-data curation ·
Scope: the published v1.0.x benchmark and the EBAO evaluator only. No generator change, no image bytes.
Root cause is owned by DeepCommit-Env `test-as-first-class` (ABTA D8/D10, `docs/spec/test-as-first-class/golden_replay.md`);
this release buys fairness on the published data while that lands.
Review record: `reeval/v102_spec/codex_review_v1.md` (to be produced, kept verbatim).

## 0. Why a symptomatic release, and the one boundary rule

The 2026-08-19/21 audit of all seven repos (census, per-repo findings, PGB study; pointers in §2)
established the root cause: the evaluator pairs the agent's **cumulative** tree with a milestone's
**DAG-local** frozen tests; the golden side never constructs or calibrates the cumulative state, and the
generator builds END tags from two vintage rules (src along the DAG, everything else from the
milestone's `last_commit` snapshot). The same test id is F2P/N2P in its owner universe and P2P in
sibling universes; agents that implement the owner correctly then fail every later-tagged sibling
cell. Binary `resolved` and the `missing == 0` gate amplify one id into many zeroed cells.

The structural fix (progress-aware test overlays, golden replay, order-invariance certificate) requires
reclassifying every universe and is therefore a new major data version. It cannot be back-applied to
v1.0.x. v1.0.2 does only what the EBAO path can do without touching images or the generator:

> **Boundary rule.** A change is in scope for v1.0.2 iff it can be expressed as (a) a `filter_list.json`
> entry, (b) a bounded evaluator behaviour behind a config key that defaults to today's behaviour,
> (c) an SRS text change, or (d) a harness bug fix already specified elsewhere — and it can be applied
> to published cells by re-tally or declarative re-evaluation (`docs/re-evaluation.md`) without re-running
> any agent. Anything that needs new image bytes, a new classification universe, or a generator change
> is out of scope and is referenced to its owner.

Everything below is score-touching and therefore carries the impact-analysis obligation of
`docs/versioning.md` (scan the corpus, report the sync, maintainer decides).

## 3. Fix design per class

### 3.1 C1 — value-level conflicts: filter in the victim universes

Mechanics. For each proved conflicting id and each victim universe listed in the census drop-list,
add the id to `test_results/<MID>/<MID>_filter_list.json` under `invalid_pass_to_pass`. The existing
`filter_evaluation_result()` path (evaluator.py:1900ff) removes it from the required set and
corrects `pass_to_pass_missing`; `collect_results` prefers `evaluation_result_filtered.json`. The
owner universe is **not** touched (there the id is F2P/N2P and must stay so).

Provenance. Every entry carries the existing per-item form plus `reason: cross_universe_conflict`,
`owner_milestone`, `evidence: <path#anchor>`, `added_in: v1.0.2`. A campaign file
`reeval/v102_c1/EXPECTATION.md` declares the (universe × id) set before any re-tally.

Why filter rather than edit `stable_classification`. The classification file is the record of what the
golden world observed; it is still true in that world. The defect is that the obligation is invalid
*for cumulative evaluation*, which is exactly what the filter list expresses per universe. The original
`evaluation_result.json` stays in place as audit trail (filter-list-only campaign rule in
`docs/re-evaluation.md`).

Limits. A filtered id removes the charge; it does not restore coverage. That is accepted: the removed
obligation was self-contradictory and carried no information about the agent.

### 3.2 C2 — compile/collection-level conflicts: skip the poisoned graft, then re-evaluate

Mechanics (new, bounded evaluator behaviour). The evaluator grafts the victim universe's frozen tests
(whole files from `test_dirs`, in-file regions via `rust_test_filter.merge_src_with_gt_tests`). When a
frozen file/region is the triggering artefact of a compile-level conflict, grafting it kills the whole
compilation unit; filtering its ids cannot bring the other tests of the unit back. v1.0.2 adds one key
to `<MID>_filter_list.json`:

```
"gt_test_graft_skip": [
  {"path": "crates/nu-protocol/tests/test_signature.rs",
   "reason": "cross_universe_conflict_compile",
   "owner_milestone": "milestone_G01_48bca0a",
   "evidence": "reeval/xuniv_20260820/nushell/FINDINGS.md#t4",
   "added_in": "v1.0.2"}
]
```

Semantics: the evaluator does not restore that file/region from the END tag when assembling the
evaluation tree for this universe; the file's ids are listed under `invalid_pass_to_pass` in the same
filter list (so they are neither required nor counted missing); everything else in the unit is graded
as usual. Default (key absent) is today's behaviour. The skip is recorded in `evaluation_result.json`
(`gt_test_graft_skipped: [...]`) so the cell's provenance shows it.

Two variants were considered: (a) **unconditional per-universe skip** (the key above); (b) trial-aware
skip only when the trial's completed set contains the owner. (b) is the precise semantics but needs
the evaluator to read trial state and changes results per trial; it is ABTA D10's job. v1.0.2 takes (a):
it is order-independent, pure data + one config key, and the coverage it gives up is exactly the
self-contradictory part. Decision 1 in §7.

Application: declarative re-evaluation of every published cell in the affected universes
(`docs/re-evaluation.md`), same v1.0.1 images, frozen snapshots; EXPECTATION declares the cells and
the direction (P2P missing must drop; nothing else may change). The compile kill currently hides every
other test of the unit, so this is the class where re-evaluation recovers the most information and
where the structural ceilings move.

### 3.3 C3 — invalid-list leakage: propagate by content identity

For each id present in any universe's `invalid_*` list, and each other universe where the same id is
required **and the test body hash is identical** (the per-repo scratch directories already hold the
body-hash sweeps), add the same entry with `reason: invalid_propagated_from:<MID>`. Identical content
is the condition; different revisions are a different test and are not propagated. Re-tally.

### 3.4 C4 — reference-unachievable obligations: golden sweep, then filter

Mechanical sweep (no agent runs): evaluate every milestone's golden END with crash visibility
(`node --unhandled-rejections=warn` for jest; Maven `-fae`; Go/cargo/pytest as today) and list every
required id (F2P/N2P/P2P) the reference solution does not achieve. Each such id is misclassified by
construction and goes to the universe's filter list with `reason: reference_unachievable`. This is the
investigation #23 asks for, generalised to all repos; the audit already found candidates outside
element: navidrome golden `sub-01` END fails to build 10 test binaries and golden `sub-02` END cannot
compile `persistence` (413 ids), go-zero has 4 universes whose baseline does not compile, scikit
`M12.1` F2P imports symbols from upstream PRs outside the milestone (#26, 237 ids).

Where a crash hid a whole suite (element), the affected published cells are re-evaluated with the
visibility flag so that recoverable tests report (the #23 batch measured 576 pass / 148 fail across the
class, so a blanket policy in either direction is wrong; the sweep decides per id). Where the suite ran
and only the obligation is wrong (scikit 237), re-tally suffices.

The scikit case needs a decision (§7, Decision 3): removing 237 F2P ids changes M12.1's effective set
for every published trial; the alternative (disclose the prerequisite in SRS) is future-only.

### 3.5 C5 — PGB: curation first, SRS only for exported symbols

Per confirmed case:

- dubbo `M003.2`: promote `TripleMutinyPublisherTest`/`TripleMutinySubscriberTest` into M003.2's own
  graded universe as F2P (verified to compile against golden `milestone-M003.2-end`). For published
  trials this moves the penalty from M003.3 (where it is a P2P of someone else's work) to M003.2
  (where it is the work). Decision 2: retroactive promotion vs. documenting only.
- ripgrep `r2094`: SRS line in `milestone_seed_a6e0be3_1_sub-01` (the bound guard is exported
  behaviour); no retroactive change (agents could not have known; the SRS fix is the fix).
- element `be3778b_1`: SRS FR3 amendment (destructive list items, `%(brand)s`); no retroactive change.
- go-zero `M023`: `TestSqlxMetric` cannot be graded at the owner (the file is `//go:build ignore`d in the
  m023 image) → filter it in the four descendant universes (`invalid_pass_to_pass`,
  `reason: pgb_owner_ungradeable`); coverage returns with ABTA EnvCompat. `TestUnmarshalNullableSlice`
  (M017 whose own image cannot compile `core/mapping`): same treatment for its descendants.

### 3.6 C6 — SRS contract lines (future-only) and the ledger

Add the contract lines in the four-part form already used for ripgrep `SummaryKind::Quiet` (name the file
and symbol; state the required behaviour; say why it does not conflict with the milestone's own
requirement; note that existing tests bind it and are not updated on the agent's behalf): the 27
avoidable ids' owners; the nushell retention clause replicated into the 10 SRSs lacking it; dubbo
M003.2's remaining bound shape; ripgrep `passthru`; element `be3778b_1` FR3; go-zero `M023`
`StartAsync`. Each line is a row in `docs/spec-debt.md` (created by this PR; `docs/versioning.md`
"Hotfix" already refers to it).

### 3.7 C7 — harness

- **#24 (identity)**: prerequisite. Its re-tally tool (`harness/e2e/rescore.py`) is the channel for every
  re-tally above; its v3 addendum already states that #24 lands before any v1.0.2 re-evaluation.
- **`residue_prune` authority**: today a src file is pruned iff it existed at START and is absent from the
  agent tar. Two pathologies follow (`pgb_B/navidrome_FINDINGS.md`, NAV-16 / NAV-01): END-only golden
  files (introduced by the universe's own golden delta) are never pruned, so at `sub-04` the frozen suites
  run against golden's components and the agent is credited 81 N2P ids it never wrote; at the descendant
  `m004` the same files are at START and are pruned, so the suites fail on missing imports and 1,245 ids
  fall into `missing`. With pruning disabled the inverse happens: golden `sub-01`'s migration file stays
  on disk next to the agent's own migration, goose derives the same `up<CamelCase>` symbol from both
  file names, `db/migrations` dies, and one filename explains the whole glm-5.3 `_003`/`_004` gap
  (47.40 vs 32.66) with an inverted gradient (naming closer to golden is punished harder). Minimal
  consistent rule: prune every src file that is neither in the agent's cumulative diff nor a TrialBase
  file, i.e. **authorship, not START presence** (golden residue is golden residue whether it arrived via
  START or END); enabled by default for the re-evaluation. This removes the false credit at `sub-04`, turns
  the deferred `m004` surprise into the same, immediate, correctly attributed failure, and removes the
  same-symbol collision. The structure binding itself (frozen tests importing golden's file names) is
  #27 / ABTA D1 territory and is not fixed here. Behind a config key defaulting to today's behaviour;
  affected navidrome cells re-evaluated.
- **`build_command` START fallback (go-zero)**: record `fallback_to_start: true` in results (already
  visible in eval logs) and exclude such cells from `resolved` in `collect_results` behind a flag
  (Decision 4). ABTA abolishes the fallback outright.
- **Maven fail-fast / UNRUN**: `-fae` for future runs; for published cells the records do not exist and
  cannot be recovered — documented, not fixed.

## 4. Re-tally and re-evaluation plan

Two channels, mirroring `docs/re-evaluation.md`:

```
Channel A (re-tally, no execution)     Channel B (declarative re-evaluation, evaluator only)
  C1 filter entries                       C2 graft skips + filter entries
  C3 propagated entries                   C4 crash-hidden suites (element)
  C4 ran-but-wrong obligations            C7 residue_prune navidrome cells
  C5 descendant filters (go-zero)
  tool: harness/e2e/rescore.py            tool: python -m harness.e2e.evaluator (frozen snapshots, v1.0.1 images)
  output: evaluation_result_filtered.json output: full cell outputs in the reeval mirror
          + rescore_manifest.json
```

Per campaign: `EXPECTATION.md` first (cells, direction, data commit, filter-list hashes), mechanical
diff, `SCORE_DELTA_<campaign>.md`, then the human-approved promotion procedure (append-only backup,
promote result **and** artifacts, sync `summary.json`, filtered-file shadowing rule). Nothing is promoted
by default.

Impact analysis (per `docs/versioning.md`): scope = cells carrying the signature **union** cells with no
valid result on the affected milestones; exclusions verified and stated. The census `census.json`
drop-list is the signature set for C1; the `missing`-channel recomputation in the per-repo findings is
the set for C2.

## 8. Acceptance criteria

- Every proved conflicting id in the census drop-list is absent from the required set of every victim
  universe after re-tally, and present in its owner universe's effective set unchanged.
- No cell outside the declared EXPECTATION sets changes (mechanical diff, per test id).
- Golden sweep report exists for all seven repos; every required id in every universe is achieved by the
  reference solution or is filtered with `reason: reference_unachievable`.
- After C1+C2, the structural ceiling (flawless agent under observed orders) recomputed from the
  per-repo findings is |DAG| for dubbo, element, navidrome, go-zero, ripgrep; nushell and scikit
  report any residual non-unity ceiling with the responsible artefacts named (their remaining cycles
  or stub bindings are out of scope and must be listed, not hidden).

- `docs/spec-debt.md` lists every SRS change shipped under v1.0.1 and v1.0.2.

## 9. What v1.0.2 does not fix (by design)

Order dependence in general (only the enumerated conflicts are removed; unknown ones remain until
ABTA D10's replay certificate); the PGB class as a class (only the five confirmed cases); scikit image
stubs; the scheduler; the scoring semantics of `resolved` itself (binary, `missing == 0`); and the
generator's two vintage rules. Each has an owner in DeepCommit-Env `test-as-first-class`
(`agent_base_test_assembly.md` D8/D10, `golden_replay.md`).
