## 0. Why a symptomatic release, and the one boundary rule

The 2026-08-19/21 audit of all seven repos (census, per-repo findings, PGB study; pointers in §11)
established the root cause: the evaluator pairs the agent's **cumulative** tree with a milestone's
**DAG-local** frozen tests; the golden side never constructs or calibrates the cumulative state, and the
generator builds END tags from two vintage rules (src along the DAG, everything else from the
milestone's `last_commit` snapshot). The same test id is F2P/N2P in its owner universe and P2P in
sibling universes; agents that implement the owner correctly then fail every later-tagged sibling
cell. Binary `resolved` and the `missing == 0` gate amplify one id into many zeroed cells.

The structural fix (progress-aware test overlays, golden replay, order-invariance evidence) requires
reclassifying every universe and is therefore a new major data version. It cannot be back-applied to
v1.0.x. v1.0.2 does only what the EBAO path can do without touching images or the generator:

> **Boundary rule.** A change is in scope for v1.0.2 iff it can be expressed as (a) a `filter_list.json`
> entry, (b) a bounded evaluator behaviour behind a config key or declarative input that defaults to
> today's behaviour, (c) an SRS text change, or (d) a harness bug fix already specified elsewhere — and it
> can be applied to published cells by re-tally or declarative re-evaluation (`docs/re-evaluation.md`)
> without re-running any agent. Anything that needs new image bytes, **new test bytes, a regenerated
> classification**, or a generator change is out of scope and is referenced to its owner.

Corollaries: promoting a test into a milestone's effective set (dubbo `M003.2`) ships new test bytes and
re-baselines a classification → out of scope (forward-only SRS line only); image-patch campaigns are out
of scope; **scoring policy does not change**: the sanctioned mechanism — validated removal of invalid obligations
through filter lists, which by construction reduces the required set and recomputes `resolved` — stays; what is
prohibited is any new rule that flips `resolved` or edits a denominator for reasons other than validated invalid
obligations (see §3.7).

Everything below is score-touching and carries the impact-analysis obligation of `docs/versioning.md`
for every class and every decision branch, including C7(i)/#24 (§6).

## 2. Two channels, one invariant

- **Channel A — re-tally** (`rescore.py`, #24 branch, extended by §5): inputs are the stored raw
  `evaluation_result.json` payloads (from `artifacts/` directories or result tars), the per-trial
  configuration / manifest data, the pinned classification per universe, and the v1.0.2 filter lists;
  outputs are regenerated `evaluation_result_filtered.json` files, per-cell delta records, and the
  promotion manifest. No container runs.
- **Channel B — declarative re-evaluation** (`docs/re-evaluation.md`): only for cells whose frozen agent
  snapshot passes that document's validity gates; the cell is re-evaluated with the v1.0.2 harness
  (test exclusions, pinned jest IPC guard, `fallback_reason`, `maven_fail_at_end`) and promoted under that
  document's procedure.

Invariant, per cell: outside the cell's **declared target id set** the test outcomes (id → status) are
identical to the baseline run; inside it only the **declared transitions** may occur (§3.x). Result
*metadata* (campaign, provenance, guard hash, fallback reason) is expected to differ and is excluded from
the comparison. Channel B's baseline for "identical outside the target set" is the same v1.0.2 harness run
with the feature disabled (C2-disabled vs C2-enabled), not the v1.0.1 bytes.

## 3. Per-class mechanism

### 3.1 C1 — conflict filters, with fail-closed validation (R1)

**File schema:** top-level optional `"version"`; absent = version 0 (today's 93 files: bucket keys only, entries are
strings or `{test_id, reason}`); version 1 adds the entry fields `class`, `evidence`, `owner_milestone`, `condition`.
**Entry schema (v1, additive):** `{"test_id", "reason", "class": "C1" | "C2" | "C3" | "C4" | "C5", "evidence":
"<reeval path#anchor>", "owner_milestone": "<id>", "condition": null | {"owner_completed_before": "<id>"}}` with
per-class required fields — C2: `exclusion_file` (and the cross-file invariant: the set of class-C2 P2P entries of a
universe **equals** the union of its exclusion files' `excluded_test_ids`); C3: `source_universe`; C4: `sweep_artifact`;
C5: `family`; C1: `owner_milestone` — under `invalid_pass_to_pass` for P2P ids, or
under either of the two F2P/N2P keys, which the evaluator treats as **one compatibility bucket**
(`fail_to_pass ∪ none_to_pass`) — validation is exact per bucket, not per key. Unknown version (> 1) is a validation error.

**Validation (R1, one function used by evaluator preflight, `generate_filtered_evaluation`, and
`rescore.py`):** for every entry, `test_id` must exist in the universe's pinned `stable_classification` in
the bucket implied by its key (`invalid_pass_to_pass` → `pass_to_pass`; `invalid_fail_to_pass` /
`invalid_none_to_pass` → `fail_to_pass ∪ none_to_pass`, preserving the evaluator's existing merged handling);
no duplicates within or across keys; no unknown ids; schema version known. P2P `required` is reduced by the
**verified intersection** (today `min(len(invalid_p2p), required)`).

**Fail-closed contract (codex v2 P0-1):**
1. *Preflight:* `run_e2e` validates the filter lists of every milestone in the trial's DAG at trial start and
   refuses to start on any error (no raw results are produced). `rescore.py` validates before touching any cell.
2. *Evaluation time* (defensive; should be unreachable after preflight): on validation error the raw result is
   still written (it is the immutable observation) **with** `filter_list_error: {...}` and
   `scoring_blocked: true`; no filtered file is written, and any pre-existing `evaluation_result_filtered.json`
   in the cell is renamed to `evaluation_result_filtered.json.stale` (the shadowing hazard of
   `docs/re-evaluation.md` §"stale filtered file"); the raw `scoring_blocked` bit overrides every derivative.
3. *Summary owner = orchestrator:* when the orchestrator processes a cell result carrying `scoring_blocked: true`
   it writes `summary.json.blocked_cells: [{milestone, reason}]` and `publishable: false` (the orchestrator owns
   every summary write; `collect_results` is read-only). *Collector:* `load_evaluation_result` reads the raw result
   first; if it carries `scoring_blocked: true` the filtered file is ignored and `is_resolved` returns False; the
   collector verifies that the trial summary lists the cell (mismatch = error), reports blocked trials, excludes
   them from aggregates, and exits non-zero if any trial in its input is non-publishable — on both the single-repo
   and the multi-repo paths, which today return 0. The normal fallback (filtered preferred, raw otherwise) is
   unchanged for all other cells.
4. *Promotion:* `rescore.py` refuses to promote any cell whose validation failed; non-zero exit.
5. *Regeneration baseline:* the filtered file is always `F(raw)` from the immutable raw payload; `F` is never
   applied to a filtered file; idempotence = `F(raw)` twice is byte-identical.

**Audit of the 93 existing filter lists (2026-08-21; re-derived independently in review v2):** 1,892 raw
entries / 1,888 unique (milestone, test_id) identities; `invalid_pass_to_pass` 419/419 present in the
universe's P2P set; `invalid_fail_to_pass` + `invalid_none_to_pass` 1,469/1,473 in F2P∪N2P; the 4 remaining
entries are dubbo `M024` `RestProtocolTest::bean argument…` ids listed under `invalid_fail_to_pass` at
`test_results/M024/M024_filter_list.json:3-6` **and** correctly under `invalid_pass_to_pass` at lines 11-14 —
the F2P copies are ineffective duplicates. Disposition: delete the 4 F2P-key copies (no score change, since
the P2P copies already apply); ledger row; R1 would reject the file until this is done.

**Cohort (Decision A — blocks implementation start):** strict 195 (912 obligations) vs inclusive 219.
**Applicability (Decision B — settled by evidence):** *blanket* vs *trial-aware*. Trial-aware needs an
**order witness**, and for the published trials **none is stored**: the capture sidecar
(`source_snapshot.integrity.json`) records the agent's submission-tag commit (`agent-impl-<mid>` →
`agent_tag_commit`), the snapshot is a path-limited `git archive` without `.git`, `summary.json` timestamps are
result-processing times, and `submission_history` only records discarded tag moves — so the ancestry
"owner's `agent-impl-<owner>` commit is an ancestor of the victim's `agent-impl-<victim>` commit" cannot be
evaluated retrospectively. Consequences: (i) **B = blanket** for v1.0.2 (the only implementable option); v1.0.2
filter lists carry no `condition` entries (R1 rejects `condition != null` until a witness exists); (ii) a
capture-time witness for future trials — sidecar field `order_witness: {self_commit, completed_before:
[{milestone, commit, verdict: ancestor | not_ancestor | unknown}]}` evaluated by `git merge-base --is-ancestor`
inside the container while the repository exists — is a **follow-up harness change** (§12), not a v1.0.2
option. Per-cell provenance for every filtered cell: effective filter ids, classification digest. Blanket removes
a passing obligation in trials where the owner had not run: no `resolved` change; `score_full` / `score_1000`
can move either way when other P2P misses remain; both signs are reported.

**F2F owners:** the 3 element ids whose owner-side bucket is F2F are filtered only on the victim side.

### 3.2 C2 — compile-level conflicts: early-phase test exclusions

Why v1's mechanism cannot work (verified): filter lists are applied after evaluation; normal END
evaluation does not graft (`gt_test_suffix == base_suffix`); START/build fallback does graft
(`evaluator.py` ~L5882-5890) and would restore a deleted file; Rust in-source regions are merged by
`harness/utils/rust_test_filter.py`. Current tree preparation order: overlay/extract → existing-file
pruning → environment and manifest hooks → GT graft (fallback only) → post-apply script → Go closure →
Rust merge (`evaluator.py` ~L5682-5813).

**Declarative input** `test_results/<mid>/<mid>_test_exclusions.json`:
```
{"version": 1,
 "entries": [
   {"kind": "file" | "rust_region",
    "path": "<repo-relative, normalized: no '..', not absolute, no symlink escape, case-exact>",
    "region": {"identity": [<kind>, <name>], "scope_path": [[<kind>, <header>, <ordinal>], ...], "occurrence": <int>}
                # rust_region only: the merge key of harness/utils/rust_test_filter.py is (scope_path, identity) with identity = (kind, name);
                # repeated identical keys are paired by occurrence index, hence the explicit occurrence (0-based)
    "tag_body_sha256": "<sha256 of the file bytes (file) or of the region's exact UTF-8 text (rust_region) at the pinned END tag>",
    "excluded_test_ids": ["<ids of tests defined in the excluded file/region; must be P2P in this universe>"],
    "recovered_test_ids": ["<ids in the same compile/collection unit expected to become observable>"],
    "unit": "<crate|package|module identifier>",
    "reason": "<universe-invariant reason>", "evidence": "<path#anchor>", "campaign": "v1.0.2-C2"}]}
```
**Application point — the last mutation before the test executable runs.** Census fact: some `test_cmd`
templates carry **mutating shell prefixes** that execute after any evaluator-side hook (dubbo `M010` re-runs
`apply_patches.sh`, `M015` runs `pre-build.sh` — both delete tests and edit POMs). v1.0.2 rule: the C2 hook runs
after tree preparation on every path (END; START/build fallback — after its graft; after post-apply hooks, Go
closure, Rust merge) and after `_apply_struct_field_fixes()` (today called at the start of `run_tests()`; for
nushell it `sed`s the principal C2 file `crates/nu-protocol/tests/test_signature.rs` itself — it is a tree
mutation and is **moved to the end of tree preparation**), and **before the repo-level `build_command` gate**
(`_check_compilation()` runs e.g. dubbo's `mvn test-compile` before `run_tests()`; a frozen test that does not
compile breaks that gate first, so the hook must precede it). The hook records the tree hash; C2 applies **only to
universes whose `test_cmd` has no tree-mutating prefix** — a census over every `test_config.json` command
classifies **tree-mutating** prefixes (scripts that write into the tree: `apply_patches.sh`, `pre-build.sh`,
`sed -i`, …) as flagged, while benign output plumbing (`2>&1 | tee`, redirection, `go test -bench`) is not a
mutation; for non-flagged universes a test asserts that the tree hash at `_check_compilation()` and at test
start equals the hook's hash.
Flagged universes (dubbo) are deferred from the C2 campaign until a `prepare_cmd` split lands (config
migration: mutating prefix → `prepare_cmd` executed before the C2 hook; behaviour byte-equivalent when
`prepare_cmd` is absent) — this forces Decision I for the dubbo rows. For `rust_region` the region is removed
from the merged file (the file is forced into the Rust merge set if the submission tar lacks it); root-level
regions are represented with `scope_path: null` (the merge removes/appends root regions wholesale today), and
`occurrence` is source order among identical keys. **Id ↔ artefact binding (per-framework provenance, produced by the campaign tool on the pinned END tree
and stored as a campaign artefact):** Rust — the region parser of `harness/utils/rust_test_filter.py` yields
(file, scope_path, identity) per region; the runtime id is the module-qualified `test.name` (`report_parser.py`),
derived by resolving the crate's `mod` tree (`lib.rs` / `mod.rs` / `#[path]`) to the region's module path, and a
selected `mod` region enumerates its contained test fns; Go — `go test -list '.*' -bench '.*' ./<pkg>` per
package (ids are `package/test_name`, incl. benchmarks; subtests map to their parent) plus a `func Test…/Benchmark…`
declaration scan of the package directory gives name → file; Ginkgo (navidrome) — scoring id is
`package::hierarchy` (`go_report_utils.py`), file from the raw report's location field; pytest — `--collect-only -q`
nodeids carry the file; jest — ids are already `file::name`; Maven — surefire report (reactor module + class,
nested / parameterized classes normalized) → `<module>/src/test/java/<pkg path>/<Class>.java`. **Validation (equalities, not subsets):** `excluded_test_ids` = the
classified P2P ids that map to the selected file/region (exactly); the artefact maps **no** F2P/N2P id of this
universe; `recovered_test_ids` = the classified ids of the same `unit` minus `excluded_test_ids`;
`excluded_test_ids ∩ recovered_test_ids = ∅`; a `kind: file` path lies inside the universe's test partition.
**Fail-closed:** unknown version/kind, duplicate entries, malformed hash, missing fields, path violation, path
not found, body hash ≠ pinned tag, ambiguous region match (occurrence out of range), or any validation equality
above failing → the cell is **not evaluated**: result written with `eval_status: "infra-invalid"`,
`test_exclusions_error: {...}`; campaign exit non-zero; such a result is never promoted (the
`docs/re-evaluation.md` validity gate is asserted by a test). **Provenance:**
`test_exclusions_applied: [{path, kind, tag_body_sha256, excluded_test_ids, recovered_test_ids, unit}]`,
`test_exclusions_sha256`. `excluded_test_ids` are also listed in the universe's `invalid_pass_to_pass`
(they are classification P2P ids that will have no record). **Absent-key equivalence:** with no exclusions
file, the prepared tree hash and the test outcomes are identical to the same harness with the feature
disabled (test); END, START-fallback and Rust-region paths are covered by tests.

**Campaign matrix:** one row per (artefact, victim universe, cell) for all 28 artefacts (`CENSUS.md` §
compile-level); ripgrep / dubbo / element rows queued or deferred **individually with a reason**
(Decision I). Expectation per cell: `excluded_test_ids` → no record (filtered); `recovered_test_ids` →
`missing → pass|fail` allowed; every other id identical to the C2-disabled run.

### 3.3 C3 — leakage propagation

An invalid entry propagates from universe A to B only if (a) the test content hash at B's END tag equals
A's (identity guard only), (b) the invalidity reason is universe-invariant, (c) the entry is written under
B's own bucket key (verified by R1), and (d) the campaign record carries the before/after id-status sets
for B's affected cells showing the permitted transition (P2P fail → filtered) and nothing else.

### 3.4 C4 — reference-unachievable obligations

**Golden triple sweep (reproducible):** the classification pipeline itself is the golden END run:
`harness/test_runner/run_milestone_tests.py --work-dir <pinned data checkout> --milestone-id <mid>
--output-dir reeval/golden_sweep_<date>/<repo>/<mid> --max-retries 3 --no-cache --test-framework <repo framework>`
(no `--force-rebuild-image`: it rebuilds and overwrites the pin) with the v1.0.2 harness at a pinned commit;
`--work-dir` is the runner's `harness_workspace/<repo>/<scenario>` layout, not a bare checkout; the runner uses the
local `:latest` image tag, so the campaign first retags the pinned digest to `:latest`, verifies the digest, and
records image digest + harness commit + data commit + framework per repo in the campaign manifest; no agent tar,
filter list, or exclusions are involved in that path. Outputs `attempt_1..3/` per-attempt results. Because the merger records only observed tests (an id
seen once and absent twice is not "flaky" to it), the campaign adds a **presence matrix** (pinned classification
ids × attempts: pass / fail / absent): candidate ⇔ non-pass or absent in all three attempts; flaky ⇔ mixed over
1–2 attempts. Each candidate gets `root_cause ∈ {classification_defect (test/src version skew), flaky, infra,
image_defect, reference_defect}` with evidence in `adjudication.json` `{id, root_cause, evidence, disposition}`;
**only `classification_defect`** may produce a filter entry (`reason: reference_unachievable`, evidence = sweep
artefact). No id is pre-classified before the sweep: the scikit `M12.1` 237 ids are *candidates* (#26), their
disposition is Decision C after the sweep.

**Crash-hidden suites (element):** the evaluator installs a jest worker IPC guard
(`_install_jest_ipc_guard`: `NODE_OPTIONS --require` preload; installation is **non-fatal** and the asset
sha256 is recorded). Campaign rules: the expected guard sha256 is pinned in the campaign config; every
included new result must carry exactly that hash, else the cell is invalid; qualification of historical
cells is by a **signature census**: a stored result qualifies iff it has ≥1 zero-record suite **and** `eval.log`
contains one of the literal crash markers pinned in the campaign config (the marker list is extracted from the
#23 batch logs before the census; an empty list fails the tool); positive and negative controls are pinned as
(trial, milestone) pairs from the #23 batch. The #23 batch's recovery split is not quoted as a number until
the census re-derives it.

### 3.5 C5 — PGB families (forward-only)

dubbo `M003.2`: SRS retention line; promotion out of scope. ripgrep `r2094`: SRS line only if `passthru`

### 3.6 C7(ii) — navidrome `residue_prune`

`compute_prune_set` inputs today: base repository files, submission tar paths, START repository files
(phase-1b guard), source filter, keep list, configured extensions, capture-excluded paths
(`residue_prune.py` ~L310-345; integration `evaluator.py` ~L3917-4045). A `cumulative_guard` mode would
need, per trial, an ordered list of the agent's own earlier snapshots (member lists + hashes, ordered by the
§3.1 commit-ancestry witness), the set equation `candidates = (base − tar) ∩ (START ∪ ⋃ earlier_snapshots)`,
capture-loss handling (a path absent from a snapshot with `integrity.ok = false` is not evidence of deletion
→ keep), mode + inputs in result metadata, and a navidrome census. Golden END trees are **not** agent
authorship evidence. Those inputs do not exist for the published trials (§3.1: no stored order witness), so
`cumulative_guard` is **not** a v1.0.2 option; C7(ii) is deferred to ABTA (former Decision E removed) and this
section stays as design debt.

### 3.7 C7(iii) — go-zero START fallback accounting

Existing fields: `base_tag`, `fallback_triggered`, `end_compile_error`, `start_compile_error`,
`build_failure_policy` (`evaluator.py` ~L1375-1382, ~L1578-1587); `collect_results.is_resolved` ignores
fallback. Add `fallback_reason: null | "end_checkout_failed" | "end_build_failed"`, populated at both
fallback sites; invariant `fallback_triggered ⇔ fallback_reason ≠ null`; historical results without the
field are reported by the collector under a derived state `legacy_unknown` (not a serialized `fallback_reason`
value); collectors surface a per-trial fallback count and the leaderboard
annotates it. Changing `resolved` or denominators for fallback cells is a scoring-formula change and is
**not** a v1.0.2 option (former Decision F options 2/3 removed); the census is published.

### 3.8 C7(iv) — Maven fail-fast

Config key `maven_fail_at_end: bool` (default false) in the **milestone test config** (where the command template
lives; `dockerfiles/<mid>/test_config.json`). The command formatter (`harness/test_runner/core/test_executor.py`)
applies it per Maven invocation: the template is split on shell `&&` / `;` boundaries, each command whose
executable token is `mvn` or `./mvnw` receives `-fae` after the executable unless it already contains `-fae`,
`--fail-at-end` or `--fail-never` (then no-op, recorded as `preexisting`); non-Maven commands are untouched;
provenance `build_flags: {maven_fail_at_end: true, applied_to: [<command index>], preexisting: [<flag>]}` in the
result. Known shapes that the rule must handle are dubbo `M017` (`--fail-never` present), `M010` (shell
prefix before `mvn`), `M020` (`mvn install && mvn test`, two invocations). Key location: a per-mode field of the
list-form config (`modes[].maven_fail_at_end`); the legacy object-form `M020` (whose `test_framework` /
`test_command_template` / `test_classes` the current loader ignores — a latent bug, not the baseline) is normalized
to one mode per class command (13 modes) plus the compile step, with the **intended 13-command behaviour** as the
equivalence baseline; the split must be quote-aware (`&&` / `;` inside quotes preserved, non-Maven argv untouched;
parser library = PR choice); provenance per mode `{mode, segment_index, original_argv, effective_argv,
disposition}`. A replayability census over dubbo cells with valid snapshots lists, per cell, whether
declarative re-evaluation is possible; permitted transitions: ids in modules after the first failing module
`missing → pass|fail`; all other ids identical to the flag-off run. Cells without a valid snapshot are
listed as unrecoverable with the reason.

## 5. #24 ordering (Decision H — blocks implementation start)

**Path (single option; the former Option 2 is the same mode run under one campaign manifest and is not a
separate design):** #24 folds and is promoted first (identity results become the baseline); v1.0.2 Channel A
runs `rescore.py --mode filter-only` (new mode next to `report` / `mirror`). Contract:

- *candidates*: the promoted identity payload per cell; a candidate is promotable in filter-only mode **only
  if** a selected `eval.json` (per-test status lists) is available — `eval_summary.json`-only tar candidates
  are `non-promotable: eval.json-unavailable` (the raw summary does not reveal which P2P ids were missing);
- *baseline*: the raw identity `evaluation_result.json` (never a filtered file); resolution locks are preserved
  exactly as `_regenerate_filtered` does today (N2P-missing state, locks reapplied);
- *inputs*: pinned classification digest, v1.0.2 filter lists (validated by R1), witness source for conditional
  entries (published trials: none → blanket only);
- *outputs*: regenerated `evaluation_result_filtered.json` + `filter_only_record.json` (effective ids, condition
  verdicts, deltas per published formula) per cell; a campaign manifest listing every cell's status
  (`promoted | non-promotable:<reason> | error:<reason>`);
- *stale outputs*: trial `summary.json` / `summary_filtered.json` are regenerated by the **orchestrator's** summary
  helpers (not by `collect_results`, which only reads); feedback files are left untouched and listed
  `stale_after_retally`; the artefact tar is regenerated when the artefact directory changes; an older filtered
  file is overwritten;
- *authority*: the serving rule is unchanged — **file-presence authority**: the collector serves
  `evaluation_result_filtered.json` when present, else raw (today's rule); with R1's fail-closed generation a
  filtered file exists iff the filter list validated, and a missing derivative for a universe with a valid list is
  a campaign error (`derivative_missing`), never silently raw; no new authority mode (strict persisted and
  threshold-DAG are not options);
- *destination*: `filter-only` writes an **append-only campaign mirror** under `--out` (like `mirror`; the primary
  tree is never written by `rescore.py`, per `docs/re-evaluation.md`); promotion is the separate step below;
- *transaction (promotion)*: unit = **trial**. The promotion tool builds a **complete** staging clone
  `<trial>.promote-<campaign>/` (metadata, every cell — promoted, unchanged and `non-promotable` copied verbatim —
  snapshots, evaluation dirs, regenerated summaries), verifies it, writes `<parent>/.promotion/<trial>.journal`
  **outside** both directories (`{live, stage, backup}` paths + state `staged → swapping → done`), renames
  live → backup and stage → live, marks `done`, and keeps the backup (append-only; supersedes the per-cell copy
  procedure of `docs/re-evaluation.md` for this campaign); deterministic recovery on restart: `staged` → delete
  stage; `swapping` with backup present and live missing → rename stage → live; `swapping` with live and stage
  both present → verify stage, redo the renames; `done` → no-op; an incomplete trial (any `error:` cell —
  `non-promotable` is not an error) is never swapped; published pointers (HF / dashboard) update only after `done`;
- *exit*: any `error:` cell → non-zero campaign exit (today's `rescore.py` returns zero with per-cell errors; the
  mode changes that).

Inherited #24 decisions, enumerated against the boundary rule: 412 non-replayable published cells → keep the
stored score and flag `identity_policy: legacy` (denominator exclusion would change a denominator → not an
option); 278 frozen pass-wins cells → the existing `--include-pass-wins` switch is the maintainer's choice
(default off = pass-wins kept); strict-vs-filtered authority → unchanged (filtered when a valid filter list exists, else raw); no threshold-DAG
authority (it would change `resolved` semantics → not an option); ginkgo mapping and Cargo timing remain #24's own items. There is no
comparator-corpus decision in #24 §9 (withdrawn from v3).
